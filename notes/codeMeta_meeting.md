## Recent CodeMeta project updates

- *CodeMeta v4.0 (released March 2026)*: New major version of the [CodeMeta](https://codemeta.github.io/) vocabulary — minimal JSON-LD/schema.org metadata for research software. v4.0 realigns CodeMeta terms with current schema.org vocabulary, adds properties including `alternateName`, `archivedAt`, and `featureList`, and removes deprecated fields. Linda is a named co-author on the v4.0 citation (`w3id.org/codemeta/4.0`) alongside founding authors Matthew B. Jones, Carl Boettiger, and Arfon Smith and the wider PMC/contributor community — see [[Professional_Background]] for her community-leadership role (Discussions activity, the AI/LLM-agent metadata proposal [#460](https://github.com/codemeta/codemeta/discussions/460), the SWHID-support proposal [#461](https://github.com/codemeta/codemeta/discussions/461)). Keywords: CodeMeta v4.0, schema.org, JSON-LD, software metadata, vocabulary release. Related: [[Reproducible_Science]], [[Professional_Background]].

- *Crosswalks / SSSOM "Rosetta stone" methodology*: The crosswalks project builds machine-actionable mappings between CodeMeta and other schemas (BibTeX, swMATH, Dublin Core, GitHub API done; GitLab API, Zenodo, DataCite, Wikidata in progress) using SSSOM (Simple Standard for Sharing Ontological Mappings). A CSV-to-SSSOM conversion pipeline with YAML metadata drives reusable, provenance-documented crosswalks (CC0 / CC-BY), with a relationship taxonomy (`same_as`, `part_of`, `more_specific_than`, and inverses) and JSON-path notation retained for nested properties. Work happens on the `sssom-methodology` branch of `codemeta/codemeta`; the mapping methodology lives at `oeg-upm/codemeta-crosswalk-mapping-methodology`. A methodology paper (see the 1 Sept call above) documents the approach and results — an August 2026 submission target was set earlier in the year but structure was still being finalised as of the 1 Sept call; a community workshop (April–May 2026) validated the method. Contributors span Software Heritage, UPM (OEG), Caltech, Arizona State University, and other institutions. Keywords: SSSOM, crosswalks, metadata mapping, FAIR4RS, LLM-assisted mapping, governance, PMC. Related: [[Reproducible_Science]], [[Data]], [[Machine_Learning]].

- *CodeMeta Party / v4.0 standards work*: See Software Heritage's ["CodeMeta Party: Shaping the future of software metadata"](https://www.softwareheritage.org/2025/12/04/codemeta-future-software-metadata/) (4 Dec 2025) for the community process that fed the v4.0 standards definition — CodeMeta as a metadata *exchange layer* linking Software Heritage, swMath, Zenodo/InvenioRDM, HAL, ascl.net, and the SciCodes registries, so metadata flows between repositories, publishers, and aggregators without bespoke converters. Keywords: CodeMeta Party, software metadata, exchange layer, SciCodes, Software Heritage. Related: [[Reproducible_Science]].

## RSECon26 — CodeMeta workshop

- *"Making Research Software FAIR with CodeMeta" (RSECon26)*: Interactive workshop (Parts I & II) at the Research Software Engineering Conference 2026, Sheffield, UK, 9–11 September 2026, co-located with IRSC26 (7–8 Sept). Co-authored and presented by Esteban Gonzalez, Linda Angulo Lopez, Anas El Hounsri, and Aida Jafarbigloo; slides and mapping handout deposited to Zenodo, DOI [10.5281/zenodo.22210982](https://doi.org/10.5281/zenodo.22210982). Teaches CodeMeta as a JSON-LD/schema.org exchange layer against research-software metadata fragmentation: auto-generating `codemeta.json` (GitHub Actions, autocodemeta, SOMEF), avoiding common metadata pitfalls, mapping other schemas into CodeMeta via structured crosswalks and SSSOM, and using LLMs to assist mapping. The "Hands-on Exercise: Mapping Metadata to CodeMeta" deck reviewed on the 1 Sept call is part of this session. Full professional-context detail and co-author roles at [[Professional_Background]]. Keywords: RSECon26, CodeMeta, FAIR software, SSSOM, crosswalks, Sheffield, workshop. Related: [[Reproducible_Science]], [[Professional_Background]].

## Nature / *Scientific Data* — "CODE beyond FAIR"

- [CODE beyond FAIR: a roadmap for reusable research software](https://www.nature.com/articles/s41597-026-06705-6) (*Scientific Data* 13:514, published 12 March 2026; DOI 10.1038/s41597-026-06705-6; preprint [inria.hal.science/hal-04930405v2](https://inria.hal.science/hal-04930405v2)): Roadmap paper by Raphaël Monat, Roberto Di Cosmo, Sabrina Granger, Konrad Hinsen, Nicolas Jullien, Daniel Le Berre, Violaine Louvet, Camille Maumet, Clémentine Maurice, and Nicolas Rougier (heavy Software Heritage / Inria authorship). Argues research software differs from data in its "living" nature and its relationship to free/open-source software, so FAIR4RS alone is not enough. Proposes a graduated, tiered roadmap around four pillars spelling **CODE**: **C**ollaborate (respond to bugs, state contribution policies, be honest about support limits, build community), **O**pen (public version-controlled source, long-term archiving, clear licences, documented authorship), **D**ocument (meaningful naming, comments, examples, tutorials, reference docs), **E**xecute (list dependencies, provide container environments, ship test suites and executable use cases). Levels let researchers with little software-engineering training improve step by step while advanced teams aim higher. Recommendations are addressed to individual researchers, institutions, funders, libraries, and publishers. Follows on from the Oct 2025 Nature commentary (doi:10.1038/d41586-025-03196-0) calling for software to get the same archive/reference/citation/credit treatment as data — see [[Reproducible_Science]] for that and Di Cosmo's "Beyond FAIR Data" course. Keywords: CODE beyond FAIR, research software, FAIR4RS, reusability roadmap, Software Heritage, Scientific Data, tiered adoption. Related: [[Reproducible_Science]], [[Professional_Background]].
