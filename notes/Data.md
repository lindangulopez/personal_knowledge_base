- *Fontainebleau Datasets: Live GBIF/OSM Queries and a Silent Filter Bug* (`research/fontainebleau-comparison/`): Three live-queried datasets for the [[Conservation|Fontainebleau comparison study]] — 345 GBIF species-occurrence records across six taxonomic groups, 20 protected-area records (all real OSM boundary polygons, unlike Limpopo's mostly-point records above), and 896 ecotourism-facility features within a 2 km forest-boundary buffer. A genuine data-pipeline bug caught during acquisition, worth keeping visible: GBIF's occurrence-search endpoint silently ignores free-text `class=`/`kingdom=` filter values — a `class=Aves` query and a `class=Mammalia` query returned byte-identical results — rather than erroring, so the working script instead resolves each group to GBIF's own numeric `taxonKey` via `/v1/species/match` before querying. France's official INPN/TAXREF biodiversity-reference service (run by the Muséum national d'Histoire naturelle, one of Linda's own former employers — see [[Professional_Background]]) returned an HTTP 403 Cloudflare bot-check, the same failure mode already documented for `whc.unesco.org` in the Côa Valley pipeline's own `acquire_unesco_heritage_zones.py`. CRS: EPSG:2154 (RGF93/Lambert-93, France's own official projection), a deliberate departure from the EPSG:3035 used for the Camargue comparison and the Côa Valley pipeline itself, since this is a French national-scale study. Keywords: GBIF Occurrence API, taxonKey, INPN, Cloudflare bot-check, Lambert-93, data pipeline bug. Related: [[Conservation]], [[Reproducible_Science]].
- *Limpopo Mining and Protected-Area Datasets: Built from Wikidata/OSM After Official Sources Failed* (`research/limpopo-mine-restoration/`): Two structured datasets (81 mining records, 78 protected-area records) assembled from scratch for the [[Conservation|Limpopo mine-restoration study]] after South Africa's two live official GIS sources — DFFE's SAPAD protected-area database and DMRE's SAMRAD mining cadastre — both proved unreachable (SAPAD: connection failure from the working environment; SAMRAD: its public viewer independently confirmed disabled by DMRE itself, no replacement yet public). Built instead on the Wikidata SPARQL endpoint plus OpenStreetMap Nominatim/Overpass, with 7 protected areas and 5 major mines individually boundary-verified against named must-include sites rather than trusting a generic bounding-box pull alone (a first `LIMIT`-based query had silently dropped Kruger National Park). CRS: ESRI:102022 (Africa Albers Equal Area Conic) for all distance/area computation — deliberately not a UTM zone, since Limpopo straddles UTM 35S/36S at exactly the province's eastern edge where the study's key distances are measured. A genuine data-quality find, preserved rather than silently corrected: 31 of 81 mining records list "rubidium" (Wikidata Q895) as a Bushveld Complex commodity, almost certainly a rhodium (Q1087) mix-up upstream in Wikidata itself, flagged in a `data_quality_flag` field in `limpopo_mining_sites.gpkg` rather than fixed. Also holds `limpopo_boundary.gpkg`, `limpopo_rivers.gpkg` (2,483 HydroRIVERS segments, unnamed — no river-name attribute in this extract), and `limpopo_connectivity.gpkg` (the Tier 2/3 candidate-linkage and pinch-point layers). Keywords: Wikidata SPARQL, OpenStreetMap, data acquisition, GeoPackage, data quality, Africa Albers Equal Area Conic. Related: [[Conservation]], [[Political_Ecology]].
- *GIS Vector Boundaries: Protected Areas and Ecological Zones*: Worth distinguishing from [[Embeddings]] up front — these are GIS **vector geometry** (polygons in a geopackage, from official cadastre/UNESCO inscription data), not ML **vector embeddings**; "vector" means two unrelated things here. The Côa Valley Eco-Connectivity notebook's `heritage_protection.gpkg` holds `unesco_alto_douro` (24,599.98 ha, an exact match to the published Alto Douro Wine Region figure) and `coa_rock_art_core` (568.62 ha) — both legal exclusions from any conservation-land-use conversion. `land_tenure.gpkg` holds `hunting_zones` (337 ICNF-cadastre polygons, 663,158 ha, split 194 associative/108 municipal/35 touristic-private) and `private_reserves` (Faia Brava — 214.6 ha in this geopackage, flagged in the source data itself as an undercount against the published 856.87 ha figure). Keywords: GIS vector data, geopackage, protected area boundaries, cadastre, UNESCO heritage, hunting zones. Related: [[Conservation]], [[Political_Ecology]].

- *GIS Raster Layers: Resistance Surfaces for the Python-Only Omniscape Analysis*: The raster counterpart to the vector-boundaries note above. The eco-connectivity notebook builds a resistance surface per functional group — land/terrestrial, water/aquatic, air/avian — each a Random Forest suitability raster trained on GBIF occurrence records and environmental covariates, plus a standalone `distance_to_road_m.tif` road-distance covariate (~1,517×862 cells; median distance to nearest road 27,564 m; only 4.4% of cells within 250 m of a road). Two penalty mechanisms are rasterized directly onto these surfaces (`build_resistance_surfaces.py`): `heritage_conflict_penalty()`, a uniform area-fill penalty from the `heritage_protection.gpkg` polygons already covered above; and `barrier_penalty()`, a distance-decayed point-based penalty from Survey123 field-barrier observations (fences, dams, roads) — deliberately different in kind from the uniform heritage fill. A 2025-wildfire fire-history penalty (~10% of the 318,000 ha valley burned) layers on top. All of it combines into a species-count-weighted multispecies connectivity surface via Omniscape-style circuit theory, run through the notebook's pure-Python (`scipy.sparse`) pipeline rather than Circuitscape/Omniscape.jl — see [[Reproducible_Science]]. Outputs (rasters, maps, a QGIS project) feed the closing chapter of the project's StoryMap — see [[Cartography]]. Keywords: resistance surface, GeoTIFF, circuit theory, Omniscape, Random Forest, road-distance covariate, fire-history penalty. Related: [[Conservation]], [[Reproducible_Science]], [[Cartography]].
