- [Web scraping is breaking the internet (and how we fix it)](https://mailchi.mp/softwareheritage/welcoming-and-serving-users-17996940?e=3e00f47ad0): Software Heritage's August 2026 community newsletter. Lead story: Director Roberto Di Cosmo's blog series on the "good enough trap" — AI crawlers repeatedly re-scraping the whole web to detect changes, wildly inefficient and pushing sites to lock down behind bot filters and paywalls, when a push-based fix (his own 1998 IETF Internet-Draft, the Remote Update Protocol) was proposed decades ago and quietly expired for lack of a champion institution; frames Software Heritage's archive-once mission as the modern answer. Also reports: Leiden University's CWTS Scholarly Communication Policy, which treats research software and datasets as primary scientific outputs and names public infrastructures like Software Heritage and Zenodo (not GitHub) as the ones offering long-term preservation guarantees; a Linux port recovered for the HP Prime G2 graphing calculator using repositories reconstructed from the Software Heritage Archive; and upcoming conference presentations by Software Heritage staff, including Linda's own CodeMeta talk at the ELIXIR FAIR-metadata workshop, ECCB 2026, Geneva, 3 September 2026 — see [[Professional_Background]]. Keywords: Software Heritage, web crawling, Remote Update Protocol, CWTS Leiden, open science policy, CodeMeta. Related: [[Data]].

- *Beyond FAIR Data: Making Research Software a First-Class Research Output* (`raw/2026-06-11-SNS-EELISA.pdf`): A 59-slide course/talk by Roberto Di Cosmo (Director, Software Heritage; Inria/Université Paris Cité), delivered 11 June 2026 — the filename suggests it was given for the EELISA European university alliance. Builds on a Nature commentary (Oct 2025, doi:10.1038/d41586-025-03196-0) calling for software to get the same archive/reference/citation/credit treatment as data, and frames the whole talk as "the how-to behind that call." Opens from Popper's reproducibility principle to argue that preserving source code itself — not just describing methods — is what makes computational research verifiable. Core technical content: the SWHID (Software Hash Identifier), an intrinsic, content-derived identifier built from a Merkle DAG of a project's full development history, which anyone can recompute offline to verify an archived copy matches the original ("a DOI answers 'which deposit?'; a SWHID answers 'exactly which bytes, and prove it'"); practical tooling for researchers — the CodeMeta Generator and an auto-derived `CITATION.cff` for describing software, and the HAL/Software Heritage curated-deposit workflow used in French research; adoption evidence, including a Spinellis et al. MSR 2026 dataset citing 30 SWHIDs and a population-genetics paper embedding SWHIDs since 2020. Closes on policy stakes: the 2019 EU Copyright Directive's "upload filter" rules, where Software Heritage helped secure a non-profit-archive exclusion, and the 2021 US Executive Order's software-supply-chain-security ("Know Your SoftWare") provisions — plus an infrastructure timeline from the archive's 2015 launch through its 2026 ENEA institutional mirror. Keywords: SWHID, CodeMeta, FAIR software, research software citation, Merkle DAG, software supply chain. Related: [[Professional_Background]], [[Data]].

- *A Reproducible, Pure-Python Connectivity Pipeline for a Data-Sparse Rewilding Landscape*: The Côa Valley Eco-Connectivity notebook (see [[Conservation]]) is explicitly framed, in its own draft paper abstract, as a reproducibility contribution rather than a methodological advance: a fully Python-based circuit-theory pipeline (`scipy.sparse` pairwise current-flow solving) built specifically so a resource-constrained conservation organization doesn't need a Julia runtime (as Circuitscape/Omniscape.jl requires) in its computing environment. The same abstract models reproducibility as including candid disclosure of a method's own limitations, not just runnable code — it reports the pipeline's Random Forest accuracy metrics as not out-of-sample validation, flags run-to-run stochasticity from an undocumented random seed, and notes a resistance-grid resampling step that dilutes fine-scale field-evidence effects. Source: `portfolio/paper-abstracts-draft.md` (abstract #1), `processed/portfolio/paper-abstracts-draft.md`. Keywords: reproducibility, pure-Python pipeline, dependency choices, validation limitations, circuit theory. Related: [[Python]], [[Conservation]].
